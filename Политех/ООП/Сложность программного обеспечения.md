Объектно-Ориентированное Программирование
Объекты изучения в рамках курса ООП:
- Программное Обеспечение (ПО)
- Подходы к разработке ПО
	- методы анализа
	- методы проектирования
	- распространенные подходы к реализации типовых задач
- Инструменты разработки ПО — языки программирования

### Свойство сложности ПО
Какое ПО является сложным?
- лабараторная работа по программированию(сортировка пузырьком) — сложность в поставленной для изучения задаче
- программы энтузиастов (web-скрапперы, персоональные chat-боты, TODO-листы) — один разработчик, не требуется поддержка

- промышленное комерческое ПО:
	- Операционные системы() — большое количество кода
	- Системы управления ЖД/авиа перевозки — взаимодействия со сложными физическими, социальными системами, Киберфизические системы
	- Поисковые системы, системы индексации и рекомендаций

### Факторы сложности ПО. Внешние
#### 1. Сложность предметной области
- Функциональные требования
	- большое количество функциональных требований для сложных систем
	- противоречивые функциональные требования
- Нефункциональные требования
	- производительность
	- удобство пользования
	- толерантность к ошибкам

**Инструменты**
Техническое задание — детальное описание требований к разрабатываемому ПО

- Сложность изложения точных функциональных требований конечного пользователя системы и их доверия до разработчика системы
- Изменение процесса в результате внедрения ПО может приводить к изменению функциональных требований

Задча группы проектирования — создать иллюзию простоты

**Роли**
аналитики

**Инструменты**
Технические задания — детальное описание требований к разрабатываемому ПО

#### 2. Организационная сложность
- Большой обьём кода сложного ПО
	- Ограниченные способности человека

- Использование различных технологий:
	- Разлчиные типы хранилищ данных
	- Поддержка различных ОС
	- Веб-интерфейс
	- Аналитические системы (машинное обучение)
	- ...
Большой штат разработчиков сложного ПО требует:
- распределение задач между командами
- передачи знаний о работе модулей ПО между командами

**Инструменты**
Git, системы управления проектами, wiki-системы генерараторы документаций

**Роли**
Product owner
Team lead
Разработчик

#### 3. Гибкость процесса разработки 
- Отсутсвие стандартных решений
- Отсутсвие готовых "базовых блоков"

Высокое сосредоточение разнородных задач в рамках компании, разрабатывающей ПО

Высокая трудоёмкость процесса разработки

**Инструменты**
Программные библиотеки, фреймворки(веб-фреймворки, фреймворки хранения данных)
