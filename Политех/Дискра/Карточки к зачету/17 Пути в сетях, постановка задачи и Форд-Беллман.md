# Билет 17. Пути в сетях: постановка задачи, метод Форда-Беллмана

> **Вопрос:** пути в сетях: постановка задачи, метод Форда-Беллмана.

## Постановка задачи

- **Сеть** — взвешенный орграф $G = (V, D, c)$. Представление: матрица весов дуг или списки смежности $list^{+}[v]$ (исходящие соседи) / $list^{-}[v]$ (входящие).
- Для пути $P: v_0 \to v_1 \to \dots \to v_k$ его **вес** $c(P) = c(e_1) + \dots + c(e_k)$ — сумма весов дуг. Путь наименьшего веса из $u$ в $v$ — **кратчайший $(u,v)$-путь**.
- **ЗКП (задача о кратчайшем пути)** — три постановки:
  1. для заданных $s, t$ найти кратчайший $(s,t)$-путь;
  2. для заданной $s$ найти кратчайшие $(s,v)$-пути до всех $v$;
  3. кратчайшие пути между **всеми парами** вершин.
- ЗКП в неориентированном графе — заменой каждого ребра $(u,v)$ на две дуги $u \to v$, $v \to u$ того же веса; в невзвешенном — весами 1.
- Алгоритм задачи (1) вынужденно решает задачу (2) (надо учесть пути до всех промежуточных вершин); задачу (3) можно решать $n$ запусками алгоритма задачи (2), но не эффективнее алгоритма Роя-Флойда-Уоршелла.
- **Веса могут быть отрицательными.** Если есть **контур отрицательного веса** (сумма весов дуг контура $< 0$), достижимый из $s$ и из которого достижим $t$, — кратчайшего пути не существует (можно накручивать контур, уменьшая вес без предела); большинство алгоритмов дают некорректный результат или не завершаются. В конечном графе веса можно сделать неотрицательными, но перекраивание данных может стоить дороже решения ЗКП.

## Метод Форда-Беллмана

Решает задачу (2) в **самом общем случае** — произвольные веса; корректен, только если нет контуров отрицательного веса.

**Идея — пошаговое вычисление:** пусть $d_k(v)$ — вес кратчайшего $(s,v)$-пути, содержащего **не более $k$ дуг**. Справедливо $d_1(v) \geq d_2(v) \geq \dots \geq d_{n-1}(v)$; длина любого пути $\leq n - 1$, поэтому $d_{n-1}(v)$ — вес кратчайшего $(s,v)$-пути. Рекуррентная формула:

$$d_k(v) = \min\{\, d_{k-1}(v),\ d_{k-1}(w) + C[w,v] \mid w \in list^{-}(v) \,\}$$

Начальное значение: $d_1(v) = C[s,v]$ (по матрице весов).

**Восстановление пути:** массив $P$, где $P[i]$ — вершина, предшествующая $i$ на кратчайшем пути из $s$ (если есть кратчайший путь $u \to v$ через $w$, то его $(u,w)$-подпуть тоже кратчайший). Путь восстанавливается с конца: $P[t]$, $P[P[t]]$, … до $s$ (в обратном порядке).

**Алгоритм** (вход: матрица весов $C$, вершина $s$; выход: $D$, $P$):
1. Для всех $v$: $D[v] = C[s,v]$ (или $+\infty$, если дуги нет), $P[v] = s$.
2. Для $k = 1, \dots, n-2$: для всех $v \neq s$: для всех $w$: если $D[w] + C[w,v] < D[v]$ — обновить $D[v] = D[w] + C[w,v]$, $P[v] = w$.
3. Вернуть $D, P$.

**Сложность:** $O(n^3)$ времени, $O(n^2)$ памяти; вариант с просмотром только $w \in list^{-}(v)$ — $O(nm)$. Модификация с `while` (повторять, пока есть изменения) в среднем быстрее, но worst-case не улучшается.
